## 0. 核心决策速览

- **正交俯视（正上方）、tile 64、单张连续地图**：第一章第二节是一张 32×64 御膳房图，不切房间、不加载；与「游戏素材大师」俯视地图编辑器的视角一致。
- **实时 8 向移动**，不是战棋；摇杆 + 大按钮，竖屏可玩。
- **玩家视野 + 敌人视野 + 背后偷袭**：玩家只能看见面朝 120°、7.5 格、无遮挡的区域；敌人有可见视锥；从背后 120°、1.2 格按「偷袭」= 无声解离，不进入战斗。
- **独立战斗场景保留给后续**：第一章第二节不做战斗；地图接敌只在剧情需要时进战斗。
- **每卷一条心防规则**，地图与 Boss 战共用同一份数据。
- **检查点在章节段落**：2026-10-31 删除「锚点」说法；只做系统层检查点（`avm.progress.v1`），对白不解释；预览模式只读，seed 可复现。

## 1. 设计目标

### 1.1 一句话

**正交俯视、单张连续的梦域地图**：玩家只能看见面朝方向的一扇光，在巡逻的视锥缝隙里移动、观察朝向、选择绕开或从背后无声解离；第一章第二节是御膳房，北门接以后的养心殿。

### 1.2 体验支柱

| 支柱 | 含义 | 落到系统 |
| --- | --- | --- |
| 看得懂 | 竖屏小屏也能一眼读出墙、路、门、敌人朝向、视锥边界 | 硬边 tile、朝向箭头、视锥常显、警戒图标、区域标题 |
| 潜得动 | 不靠反应，靠观察巡逻路线和视线 | 玩家视野/迷雾、巡逻路径、视锥、听觉、掩体、躲藏 |
| 先手值钱 | 从背后接近能安静地改变局面 | 背后 120°、1.2 格、一键无声解离 |
| 一张图 | 不切房间、不读条，梦域像一座真地方 | 32×64 连续地图、跟随相机、区域标题、目标箭头 |
| 不添堵 | 手机竖屏、失败有退路 | 摇杆 + 大按钮、短检查点、失败卡「再进去」 |

### 1.3 不做

- 不做开放世界、程序生成迷宫；第一章只做一张 32×64 御膳房图。
- 不做实时动作战斗；第一章第二节不做战斗，偷袭 = 无声解离。
- 不做房间切换/加载；地图是一整张。
- 不做房间制小地图；用区域标题 + 目标箭头。
- 不做地图编辑器产品功能；M1 用手写数据 + Tiled 可选导出。
- 不做多人、联机、UGC。

## 2. 核心循环

```
落点（小白送进御膳房，删掉锚点说法）
  → 单张地图探索（移动 / 观察 / 潜行 / 躲藏）
  → 敌情判断（绕开 / 等转身 / 背后偷袭 / 被发现）
  → 世界回应（敌人化光 / 警戒上升 / 失败重开）
  → 剧情推进（门开 / 老麦出现 / 善变）
  → 下一段更难的观察
```

| 动词 | 输入 | 结果 |
| --- | --- | --- |
| 走 | 左摇杆 / WASD | 8 方向移动，撞墙滑行；视锥跟走 |
| 跑 | 摇杆推到底 / Shift | 速度 230，噪音 4 格，警戒 ×1.35 |
| 潜行 | 潜行键 | 速度 80，警戒 ×0.55 |
| 看 | 靠近可交互物 | 提示气泡、调查/开门/拾取 |
| 偷袭 | 背后窗口按「偷袭」 | 无声解离；不进入战斗 |
| 躲 | 靠近干草堆/橱柜/屏风 | 进入躲藏；敌人视锥不判定 |
| 变 | 剧情触发善变 | 变成老肯/老麦；巡逻/门卫不认 |

## 3. 视角、尺度与镜头

### 3.1 基准

| 项 | 值 | 说明 |
| --- | --- | --- |
| 设计宽 | **720** | 固定，所有坐标按 720 写 |
| 设计高 | **1280–1600** | 由视口比例算，底部 UI 贴底、场景区拉伸 |
| tile | **64×64 设计单位** | 32×32 美术像素 × 2（见 ART-STYLE） |
| 第一章地图 | **32×64 tile** = 2048×4096 | 单张连续御膳房，约 2.8 屏宽 × 2.6–3.2 屏高 |
| 分区 | 9–24 行 × 26 列 | 柴房/灶房/备膳间/库房/传膳廊，只做标签不做加载 |
| 最小通道 | **2 tile = 128** | 玩家脚盒 56+16 能过；老麦路径 ≥3 格 |
| 可见范围 | 11.25 列 × 20–25 行 | 竖屏适合纵向潜入；相机跟随，不做横向大平原 |

- **正交俯视（正上方）**：相机垂直向下看地面，正方形 tile 网格；和「游戏素材大师」的俯视地图编辑器同一视角。不做 3/4、不做等距菱形、不做 45° 旋转、不做墙面透视。
- 墙、柱、家具都是俯视平面 tile/贴图；高度感只靠描边、阴影和层叠，不画“正面墙 + 顶面”的立面。
- 角色用 8 向 top-down sprite（四正 + 四斜各一套），不是 3/4 侧身立绘；朝向由 sprite 与脚下小箭头共同表达。

### 3.2 角色与碰撞

| 对象 | 美术尺寸 | 设计尺寸 | 碰撞盒（脚下） |
| --- | --- | --- | --- |
| 玩家 | Q 版 160×400 帧 | 显示约 98×246 | **56×18**，padding 8，贴脚底 |
| 普通敌人 | 48×64 | 96×128 | 48×28 |
| 精英 | 64×80 | 128×160 | 64×32 |
| Boss | 96×96 起 | 192×192 起 | 96×48 |
| 门 | 1 tile | 64×64 | 无，触发区 |

碰撞盒只覆盖脚底，允许上半身与墙、柱子视觉重叠，避免“人物被墙吃掉一半”的廉价感；遮挡用前景层和半透明处理。

### 3.3 镜头

- 相机：`setZoom(plan.scale)` + `startFollow(player, true, 0.12, 0.12)`；deadzone **120×180**。
- 地图不再叠一层世界缩放；像素素材按 2× 设计尺寸导出或整数放大。
- 相机 bounds = **整张地图**（2048×4096）；地图边缘夹住，不露黑边；开局 `centerOn` 出生点并夹在边界内。
- **相机一滚动，所有输入命中必须改屏幕坐标**：原生 UI（摇杆/提示）`setScrollFactor(0)`，命中用 `pointer.x / plan.scale`；世界对象才用 `camera.getWorldPoint`。沿用 `pointer.worldX` 会让摇杆和「点屏幕推进对话」错位。
- 震屏只用于偷袭/被发现/重物落地；`prefers-reduced-motion` 时关闭震屏与慢动作。
- 不做房间切换淡出；区域切换只用左上角标题淡入 2 秒。

### 3.4 竖屏画面分区

```
┌────────────────────────────┐
│ 目标条 / 区域名          菜单 │ 0–96
├────────────────────────────┤
│                            │
│         场景 / 地图          │ 96–(H-200)
│                            │
├────────────────────────────┤
│ 摇杆          交互 偷袭 潜行 │ H-200–H
└────────────────────────────┘
```

- 顶部 96、底部 200 为 HUD 安全区；地图内容不得把关键信息只放在这两条带里。
- 设计高 1600 时，多出的 320 全部给场景区，HUD 仍贴底。
- **不做小地图**（会把巡逻变成雷达）；用左上区域名 + 屏幕边缘目标箭头 + 地标。

## 4. 关卡结构：房间图（已作废）

> **已作废（2026-10-31）**：第一章改为单张连续地图。下面 4.1–4.3 只作历史参考；现行结构见 [`DESIGN-KITCHEN-MAP.md`](DESIGN-KITCHEN-MAP.md) §2 与 [`DESIGN-CH01-EXPLORE.md`](DESIGN-CH01-EXPLORE.md) §3。

### 4.0 第一章（现行）：一张连续地图

- 32×64 格、tile 64、2048×4096；柴房→灶房→备膳间→库房→传膳廊，五个分区只做标签，不做加载。
- 出生点在柴房 (6,55)；传膳门在北墙 (14–17,0–3)，是养心殿接口；门从外面闩着，第二幕才开。
- 三条幻影巡逻 + 一个静止教学御厨 + 一个矿工门卫；三个躲藏点（干草堆/橱柜/屏风）。
- 无房间切换、无门读条、无小地图；区域名 + 目标箭头 + 记忆迷雾负责寻路。

### 4.1 一章 = 一个房间图（历史）

每章 **8–12 个房间**，不是一张连续大地图。房间类型：

| 类型 | 作用 | 数量 |
| --- | --- | --- |
| 入口房 | 玩家从锚点进入的落点，教学/氛围 | 1 |
| 回廊 | 连接、巡逻、第一次接敌 | 2–3 |
| 探索房 | 支线宝箱、线索、可选战斗 | 2–3 |
| 锚点房 | 存档/休整，通常在中段 | 1 |
| 主厅 | 解谜/机关/精英 | 1 |
| Boss 前厅 | 不可回头点、补给 | 1 |
| Boss 房 | 心防战场 | 1 |

### 4.2 房间图示例（卷一·宫廷）

```
[锚点·序]──[入口]──[丹陛回廊]──[中庭]──[王座前厅]──[Boss·王座]
                         │            │
                     [侧殿·宝箱]   [锚点·中庭]
```

- 实线 = 双向门；侧殿是可选支线，用“锁 + 钥匙旗标”控制。
- 中庭是回环枢纽：玩家可以绕开一组巡逻，也可以正面清掉拿素材。
- Boss 前厅关门后不可回退；进入前自动提示“是否休整”。

### 4.3 房间状态

| 状态 | 含义 | 存盘点 |
| --- | --- | --- |
| `unvisited` | 未进入，小地图只显示轮廓 | 否 |
| `visited` | 进入过，显示门与锚点 | 房间切换时 |
| `cleared` | 精英/Boss 已清除，或关键旗标完成 | 战斗胜利时 |
| `locked` | 门被旗标锁住 | 否 |

小地图只画**房间图**，不画 tile 级地图：当前房间高亮、已访问房间实线、未访问虚线、锚点/宝箱/Boss 用图标。竖屏右上角 160×150 足够。

## 5. 地图数据格式（已作废）

> **已作废（2026-10-31）**：下面的多房间 JSON / `MapRoom` 契约只作历史参考。第一章现行数据是 `src/map/types.ts` 的 `RoomDef`（单张 32×64，可选 `patrols / hides / triggers / sightBlockers`），形状见 [`DESIGN-CH01-EXPLORE.md`](DESIGN-CH01-EXPLORE.md) §10.1。

### 5.1 原则

- **房间是唯一数据单位**，一章一个 `rooms/*.json` 或一个 `chapter.room.ts` 汇总；不进运行时热更。
- 用 ASCII 画碰撞与地标，方便 review diff；对象用数组补充。
- 构建期校验：行宽、边界、出生点、门连通、巡逻点可走、锚点唯一、旗标引用存在。
- M1 不做运行时地图编辑器；Tiled 只作为可选导出源，导出后仍要过校验脚本。

### 5.2 类型契约

```ts
type TileChar = '#' | '.' | ',' | '=' | 'A' | 'P' | 'C' | 'E' | '~';

interface MapRoom {
  id: string;                 // ch01.entry
  chapter: string;            // ch01
  title: string;              // 梦域·丹陛回廊
  size: [number, number];     // [w, h]，w*64 × h*64 设计单位
  tileset: string;            // dream.palace
  ascii: string[];            // h 行，每行 w 个字符
  links: DoorLink[];
  objects: MapObject[];
  minimap: [number, number];  // 房间图坐标，格子单位
  bgm?: string;
  rule?: string;              // 心防规则 id
  note?: string;
}

interface DoorLink {
  at: [number, number];              // ascii 中 '=' 的坐标
  to: { room: string; at: [number, number] };
  lockedBy?: string;                 // 旗标 / 钥匙
  label?: string;                    // “通往中庭”
}

type MapObject =
  | { type: 'spawn'; id: string; at: [number, number]; facing: 'up' | 'down' | 'left' | 'right' }
  | { type: 'anchor'; id: string; at: [number, number]; title: string }
  | { type: 'chest'; id: string; at: [number, number]; loot: string; flag: string }
  | { type: 'patrol'; id: string; enemy: string; path: [number, number][]; pauseMs?: number; facing?: 'up' | 'down' | 'left' | 'right' }
  | { type: 'trigger'; id: string; at: [number, number]; size: [number, number]; event: string; once?: boolean }
  | { type: 'npc'; id: string; at: [number, number]; speaker: string; script: string }
  | { type: 'cover'; id: string; rect: [number, number, number, number]; kind: 'bush' | 'shadow' | 'curtain' }
  | { type: 'hazard'; id: string; rect: [number, number, number, number]; kind: string; damage: number };
```

坐标一律用 **tile 整数坐标**；运行时换算 `x * 64 + 32`（格中心）。角色脚底点单独存 `design x/y`。

### 5.3 ASCII 图例

| 字符 | 含义 | 可走 |
| --- | --- | --- |
| `#` | 墙 / 实心障碍 | 否 |
| `.` | 地面 | 是 |
| `,` | 装饰地面（地毯/草/水纹） | 是 |
| `=` | 门（必须配 `links`） | 是，触发 |
| `A` | 锚点（必须配 `objects`） | 是 |
| `P` | 默认出生点（必须配 `spawn`） | 是 |
| `C` | 宝箱（必须配 `chest`） | 是 |
| `E` | 巡逻起点（必须配 `patrol`） | 是 |
| `~` | 不可走装饰（矮墙/深渊） | 否 |

### 5.5 校验规则

1. `ascii.length === size[1]`，每行长度 `=== size[0]`。
2. 最外圈必须是 `#` 或 `=`。
3. 每个 `P` 有且只有一个 `spawn`；每个 `A` 有且只有一个 `anchor`；每个 `C` 有且只有一个 `chest`；每个 `E` 有且只有一个 `patrol`，且巡逻路径首点等于该格。
4. 每个 `=` 有且只有一个 `links`；双向门两侧 `to` 互为回指。
5. 巡逻 `path` 的每一点必须是可走格，且相邻点可直线到达。
6. 所有门、锚点、宝箱从出生点可达（BFS，考虑 `lockedBy` 时按解锁后算）。
7. `rule` / `lockedBy` / `loot` / `event` 必须在注册表里存在。
8. `minimap` 不与其他房间重叠。

## 6. 移动、碰撞、镜头

### 6.1 输入

| 输入 | 触屏 | 键盘（调试） |
| --- | --- | --- |
| 移动 | 左下浮动摇杆（半径 96） | WASD / 方向键 |
| 跑 | 摇杆推到底（>0.85） | Shift |
| 潜行 | 长按潜行键 | Ctrl / Shift |
| 偷袭 | 右下「偷袭」键（仅背后窗口） | J |
| 交互 | 右下「交互」键（自动显隐） | E |
| 暂停 | 右上角 | Esc |

摇杆 200×200 设计单位的响应区，knob 88；攻击/交互按钮 ≥ 112 设计单位（约 60 CSS px），保证拇指命中。

### 6.2 参数

| 参数 | 值 |
| --- | --- |
| 走速 | **140 设计单位/秒**（约 2.2 tile/s） |
| 跑速 | **230**（摇杆推到底 / Shift） |
| 潜行 | **80** |
| 加速度 / 减速度 | 900 / 1400 |
| 脚步噪音半径 | 走 1.5 tile / 跑 4 tile / 潜行 0 |
| 偷袭窗口 | 背后 120°、≤1.2 tile、警戒 <0.6；无正面攻击弧 |

### 6.3 碰撞

- 8 方向输入先归一化，避免斜向加速。
- **分轴解算**：先 X 后 Y；撞墙时保留另一轴速度，自动贴墙滑行。
- 拐角不切角：斜向移动若 X/Y 单独都不可走，则整体停住。
- 门洞、走廊最小宽度 **2 tile**；玩家脚盒 56 + padding 16，留 40+ 的容错。
- 斜坡/台阶不做高度，改为“视觉台阶 + 可走地面”。

### 6.4 朝向与动画

- 角色 8 向朝向（上/下/左/右 + 四斜），输入两轴占比接近时取斜向；停下保留最后朝向。
- 状态机：`idle → walk / sneak / run → interact / hide → takedown`。
- 偷袭锁移动 0.35s；无受击/无敌帧（第一章第二节不主打动作）。
- 像素 sprite 用 NEAREST；残影/光效用 LINEAR。

### 6.5 深度排序

- 地面层固定 depth 0；地面贴花 10。
- 所有“会挡人”的对象按**脚底 y** 排序：`depth = 100 + y`。
- 前景层（吊灯、门框、树冠）固定 9000，玩家走到后面时对该前景 sprite 做 0.45 透明度渐变。
- 敌人、玩家、宝箱同一套规则，避免“站在宝箱后面却画在宝箱上”。

## 7. 交互与检查点

### 7.1 交互规则

- 候选：距离 ≤ 88 设计单位，且大致在朝向侧（背后交互用“附近最近”兜底）。
- 同时多个候选时优先级：剧情触发器 > 门 > 躲藏点 > 宝箱 > NPC > 可破坏物。
- 交互提示用浮动气泡 + 图标，不写长句；长文案进对话框。
- 交互锁移动 0.2s，防止连点开门。

### 7.2 检查点（无锚点）

> 2026-10-31 用户决定删除「锚点」及“时空裂缝 / 存档点 / 读档”说法。游戏只保留系统层检查点，对白不解释。

| 功能 | 规则 |
| --- | --- |
| 自动进度 | 进入章节段落、完成关键剧情时写 `avm.progress.v1`（预览不写） |
| 章节继续 | 标题「继续游戏」从最近的章节检查点进入；不是战斗内存档 |
| 失败重开 | 只回到本节内部检查点（`entry/gate/follow`），敌人重置、剧情旗标恢复 |
| 回血/传送/稳定度 | **不做**；没有锚点经济 |
| 预览 | `StageLaunchContext.preview === true` 时禁写档，失败卡仍可重开同一舞台 |

> 原著“三次休息 24 小时”只作为小说设定保留；游戏内不出现。

### 7.3 门、宝箱、触发器

- 门：`lockedBy` 旗标满足才开；开门动画 0.4s；Boss 门反向锁，进战后不可退。
- 宝箱：一次性 `flag`；打开后换成开启贴图；掉落进战斗/背包系统（M2）。
- 触发器：矩形区，进入即发；`once` 控制是否重复；事件交给剧情模块，不在场景里硬编码台词。
- NPC：`script` 指向 `src/story/` 的对话数据；地图只负责朝向与交互。

### 7.4 地图偷袭

- 「偷袭」只在背后窗口可用：敌人未追击、警戒 <0.6、玩家在背后 120°、距离 ≤1.2 tile。
- 命中 = 无声解离，敌人化为光点消散；不进入战斗、不触发警报。
- 正面/侧面/已追击：按钮不出现；玩家只能跑/躲/绕。
- 剧情需要的地图处决（老肯/老麦）走同一套判定，但由剧情脚本给窗口。

## 8. 视野、巡逻与潜行

> 2026-10-31 现行版本：**玩家也有视野**；被发现不再进战斗，而是失败/重开。下面是第一章第二节基线；完整设计见 [`DESIGN-CH01-EXPLORE.md`](DESIGN-CH01-EXPLORE.md) §3–4。

### 8.0 玩家视野与迷雾

- 视锥 **120°（±60°）、7.5 tile**，随行走方向转；脚下 1.5 tile 环境光。
- 遮挡只认 `#`（墙/灶台/柜/屏风）；`o` 矮障碍挡路不挡视线。
- 三层可见：**当前可见 100% / 已探索记忆 35% / 未探索 8%**；记忆层不显示敌人、视锥、交互物。
- 视锥用射线求多边形；12Hz 重算；屏幕空间 RenderTexture：黑底 → 记忆格压暗 → 擦出当前视锥。
- 敌人**身体**只在身体位置进入玩家可见层时绘制；**视锥**与玩家可见区域有交集就绘制（可只看到锥尖）；被盯上时屏幕边缘给「被注视」提示，避免“被看不见的东西抓住”。

### 8.1 敌人状态机

```
PATROL ──看见/听见──► SUSPICIOUS ──警戒满──► CHASE ──抓住──► 失败
   ▲                      │                    │
   │                      └──失去视线 1.5s────┘
   └────────── RETURN ◄──── 搜索 4s / 超出拴绳 8 tile
```

| 状态 | 行为 | 玩家应对 |
| --- | --- | --- |
| `PATROL` | 沿路径走，到点停 1.0–1.5s，左右扫视 ±60° | 绕背、等转身 |
| `SUSPICIOUS` | 停步、转向可疑点、头顶 `?`，警戒条 0→1 | 潜行/进掩体/停止跑动 |
| `CHASE` | 追击，头顶 `!`，移速 170；距离 <40 持续 0.3s = 失败 | 拉开、绕角、躲藏 |
| `SEARCH` | 到最后一见位置，四处看 4s | 屏住呼吸、别动 |
| `RETURN` | 返回巡逻路径，警戒清零 | 跟背、换路 |

### 8.2 敌人视线

- 视锥：幻影 **100°（±50°）、4.5 tile**；矿工 **120°、5.5 tile**。
- 视线遮挡：每 0.1s 对玩家脚底做一次 tile 级 raycast，`#` 阻断；`o` 不阻断。
- 警戒条增速：`0.85/s × 距离系数 × 姿态系数 × 伪装系数`。
  - 距离系数 `clamp(1 - dist/range, 0.35, 1)`；
  - 走路 ×1.0；潜行 ×0.55；跑动 ×1.35；躲藏 ×0；
  - 善变伪装 ×0（门卫/巡逻都不认）；**不做光照系数**（本节没有动态光）。
- 脱离视线 1.5s 后警戒条以 `0.5/s` 衰减；到 0 回 `PATROL`。
- 听觉：跑动 4 tile、走路 1.5 tile、偷袭 1.5 tile；听到后进入 `SUSPICIOUS` 并走向声源，不直接追击。
- 可疑阈值 0.35（`?`），追击阈值 1.0（`!`）；发现前有 0.35s 可疑停顿，追击前有 0.4s `!` 定格。

### 8.3 追击与寻路

- 8 方向 A*，网格上限 400 节点；禁止贴角斜穿。
- 路径每 0.5s 重算一次；目标点被占时停在 40 距离外。
- 拴绳：离出生点 > 8 tile 或丢失目标 4s → `RETURN`。
- 追击中不触发其他敌人的“连锁仇恨”；但同房间敌人被攻击会共享一次警觉（+0.5）。

### 8.4 善变（第一章第二节的脚本化版本）

剧情里“解命中后变成目标、读取记忆、限时”。本节只做脚本化名场面，不做资源槽：

| 项 | 规则 |
| --- | --- |
| 触发 | 第一次偷袭老肯后自动激活；不手动选目标 |
| 效果 | 外观变老肯；巡逻/门卫的视线判定视为“梦中人”（×0） |
| 破绽 | 2 格内奔跑、撞到老麦、主动攻击/偷袭、被门卫贴脸检查会暴露 |
| 时长 | 10:00 徽章只作剧情压力，不做失败计时；本节结束时仍在 |
| 退出 | 剧情推进到“变成老麦”时覆盖；不做手动解除 |
| 未来 | M2 再做“自由换装/套话/资源槽”；本节不实现 |

- 巡逻/门卫在伪装状态下不进入 `SUSPICIOUS`；但它们的视锥仍会画出来，玩家能看见“它们没认出我”。
- 老麦的疑心是另一套：距离/奔跑/应答，和敌人的警戒条分开。

### 8.5 被发现与恢复

- 被发现不是立刻失败：`SUSPICIOUS` 给玩家 0.35s 停步窗口；`CHASE` 后可以跑/绕角/躲藏。
- 甩掉：脱离视线 1.5s → 敌人到最后一见位置 `SEARCH` 4s → 回 `RETURN`；玩家在掩体里就搜不到。
- 抓住：`CHASE` 中距离 <40 持续 0.3s → 失败卡「被发现了」→ 最近检查点。
- 第一章第二节**不进战斗**；四档接敌/背袭先制是后续战斗接入的内容，见 §9（已标作废）。

## 9. 接敌与偷袭判定（战斗接入用；第一章第二节不启用）

> **2026-10-31**：第一章第二节的偷袭是无声解离，不进战斗；下面四档接敌保留给后续“地图→独立战斗”的接入，第一节的 1v1 剧情战不受影响。

### 9.1 角度判定

用敌人朝向向量与“敌人 → 玩家”的单位向量求点积：

```ts
const toPlayer = normalize(playerPos - enemyPos);
const cos = dot(enemyFacingVec, toPlayer);

if (cos <= -0.5) grade = 'back';   // 玩家在敌背后 120° 扇区
else if (cos >= 0.5) grade = 'front'; // 正面 60°
else grade = 'side';               // 侧翼
```

只有敌人处于 `PATROL` / `SUSPICIOUS` 且未发现玩家时，`back` / `side` 才成立；已经 `CHASE` 一律按 `front` 或 `enemy`。

```
            敌人朝向 →
   [玩家·背后]   (敌人)   [正面]
        back      side      front
```

### 9.2 四档接敌

| 判定 | 条件 | 战斗开局（详见战斗文档 §9） |
| --- | --- | --- |
| **背袭** | 未警觉 + 背后 120° + 玩家先攻击 | 我方先制 1 轮；敌人背对我方入口排；首次命中必背刺；伪装直接破碎 |
| **侧袭** | 未警觉 + 侧翼 | 我方先制 1 轮；不自动背刺 |
| **正面** | 未警觉但正面，或已警觉 | 按 SPD 正常排序 |
| **被袭** | 追击接触 / 玩家被抓住 | 敌方先制 1 轮；我方首轮不回 EP |

### 9.3 地图 → 战斗契约

```ts
interface EncounterRequest {
  battleId: string;                 // battle.ch01.corridor
  seed: number;
  ambush: 'back' | 'side' | 'front' | 'enemy';
  entryWing: 'left' | 'right';      // 玩家从哪一侧进入战场
  enemies: { id: string; slot: 0 | 1 | 2; facing: 'left' | 'right' }[];
  source: { roomId: string; objectId: string };
  rule?: string;                    // 心防规则
}

interface EncounterResult {
  outcome: 'victory' | 'escape' | 'defeat';
  rounds: number;
  party: { id: string; hp: number; ep: number }[];
  defeated: string[];               // 敌人实例 id
  loot: string[];
  seed: number;
  logHash: string;                  // 回放/验收
}
```

- `entryWing`：玩家从敌人左侧接近 → `left`，右侧 → `right`；背袭时敌人初始朝向背对该侧。
- 队伍站位沿用上一场战斗；接敌时先保证入口侧至少 1 人（优先郑卿/周全），若入口侧已满 2 人，第三人自动放另一侧，第四人补空位。
- `seed = hashSeed(saveSeed, chapter, roomId, objectId, encounterCount)`；同存档同遭遇可复现。
- 战斗包 `battle.common + battle.<id>` 在进入接敌区时预取，用白闪/碎裂转场遮住加载。

### 9.4 战后回写

| 结果 | 地图侧 |
| --- | --- |
| 胜利 | 移除敌人实体、标记 `cleared`、开门/掉宝、自动存档（预览不写） |
| 撤退 | 玩家退到接敌前 2 tile，敌人保持警觉并恢复 30% maxHP；不自动存档 |
| 失败 | 回最近检查点，敌人重置，队伍 50% HP/EP；**无锚点/稳定度** |

## 10. 心防（地图规则）

心防是梦主潜意识的一条“荒诞但致命”的规则，每卷至少一条，地图与 Boss 战共用同一份数据。

```ts
interface DomainRule {
  id: string;
  title: string;
  text: string;                     // 进入梦域时的规则卡
  canRun?: boolean;
  alertMultiplier?: number;
  onEnterRoom?(ctx: RuleContext): void;
  onTick?(ctx: RuleContext, dtMs: number): void;
  onViolate?(ctx: RuleContext): void;
  battleRuleId?: string;            // 同一规则在战斗里的版本
}
```

| 示例 | 规则 | 玩法后果 |
| --- | --- | --- |
| 宫廷·僭越 | 王座厅内不可背对王座（不可向下走） | 向下移动累积“僭越”，3 层触发禁卫巡逻 |
| 游乐园·不许跑 | 梦域内禁止奔跑 | 跑动 0.5s 立即全场警觉 |
| 武侠·冰狱 | 冰面滑行，松手继续滑 2 tile | 转弯/停步变难，接敌角度更难控制 |
| 剧院·追光 | 聚光灯外视线判定 ×2 | 必须贴着光斑走，路线被限制 |

规则必须**进场可见**（规则卡 + HUD 图标 + 违规反馈），不做隐藏惩罚。预览参数 `rule=` 可强制某条规则，方便验收。

## 12. 美术、资源与性能

### 12.1 美术

- 每卷一套 tileset + props，主色按 ART-STYLE：宫廷金红、游乐园糖果、武侠水墨冷光……
- tile 32×32 美术像素；墙用 3×3 bitmask 自动拼接（47 图块），地面 4–6 种变体按 seed 撒。
- 俯视分层：地面 → 墙/柱 → 角色 → 前景 → 光照/浮尘 → 暗角。地图本身不改变透视；光效用加法混合的 sprite，不做实时光照。
- 同屏最多 4 个加色光源；低端机降级为 1 个 + 暗角。

### 12.2 资源与预算

| bundle | 内容 | 预算 |
| --- | --- | --- |
| `map.common` | 交互图标、警戒图标、通用 UI、玩家地图图集 | ≤ 2 MB |
| `map.<chapter>` | 本章 tileset、props、房间 JSON、BGM | ≤ 6 MB |
| `battle.common` | 战斗 UI/技能图标/特效 | ≤ 3 MB |
| `battle.<id>` | 单场战斗背景/敌人图集 | ≤ 5 MB |

- 房间 JSON 单房 ≤ 24 KB；一章合计 ≤ 200 KB。
- 图集 1px extrude + 2px padding；tileset 单张 ≤ 2048×2048。
- 禁止在场景里 `this.load.*`；所有资源进 `bundles.ts`，跑 `assets:scan` + `assets:check`。

### 12.3 性能

- 同房间最多 8 个巡逻敌人；超出用脚本触发器分批激活。
- 敌人 AI 每 0.15s 一次视线检测，每 0.5s 一次寻路；远处（>1.5 屏）休眠。
- 粒子池复用；战斗/地图转场不新建纹理。
- 目标 60fps；低端机允许 30fps，降级顺序：关体积光 → 关残影 → 降粒子 → 关前景透明度渐变。

## 13. 存档、确定性与预览

### 13.1 存档结构

> **2026-10-31 现行**：第一章第二节只用 `avm.progress.v1` 的章节检查点（`ch01.kitchen` / `ch01.kitchen.done`）+ 场景内部检查点（`entry/gate/follow`）；下面的 `MapProgress` 是未来多房间版本的草案，**锚点字段已作废**。

```ts
interface MapProgress {
  version: 1;
  chapter: string;
  roomId: string;
  at: { x: number; y: number };
  facing: 'up' | 'down' | 'left' | 'right';
  flags: Record<string, boolean | number>;
  visited: string[];
  cleared: string[];
  defeated: string[];               // 敌人实例 id
  party: { id: string; hp: number; ep: number }[];
  playTimeMs: number;

```

- 写档点：进入章节段落、完成关键剧情、战斗胜利（未来）。战斗中不写档。
- 版本迁移：`version` 不匹配时走迁移函数；M1 只支持 v1。
- 预览模式：只读；`launchStage()` 注入的 `preview` 为 true 时禁用写档/成就。

### 13.2 确定性

- 巡逻相位、地面变体、掉落、AI 犹豫时间全部走 `src/dev/random.ts` 的 `mulberry32` / `hashSeed`。
- 禁止 `Math.random()` / `Date.now()` 参与玩法；动画缓动可以用时间，但不能影响判定。
- 同一 seed + 同一操作序列 → 同一巡逻路线/接敌判定/战斗开局。

### 13.3 舞台预览

地图作为可玩场景必须登记 `src/dev/stage-catalog.ts` 和 `scene-keys.ts`：

| stage id | 内容 | 验收 |
