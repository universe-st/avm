# 地图系统设计（正交俯视）

> 状态：M1a 已实现单房间子集（2026-10-25 起为 50×54 俯视寝室、32px 地图缩小到 720 宽、ASCII 碰撞、交互、固定相机）；多房间/门/巡逻/视线/潜行/善变/小地图仍后置。本文其余部分仍是后续目标。
>
> 关联文档：[战斗系统](DESIGN-BATTLE.md)、[剧情圣经](STORY-BIBLE.md)、[美术风格](ART-STYLE.md)、[舞台预览](STAGE-PREVIEW.md)、[资源规范](RESOURCE-SPEC.md)。

## 0. 核心决策速览

- **正交俯视（正上方）、tile 64、一屏一屋**：与「游戏素材大师」俯视地图编辑器的视角一致；一章 8–12 个房间，小地图只画房间关系。
- **实时 8 向移动**，不是战棋；摇杆 + 大按钮，竖屏单手可玩。
- **巡逻视锥 + 背袭判定**：背后 120° 接敌 = 背袭，战斗先制并自动背刺。
- **独立战斗场景**：地图只负责探索、接敌与战后回写。
- **每卷一条心防规则**，地图与 Boss 战共用同一份数据。
- 存档在房间切换/战斗胜利/锚点；预览模式只读，seed 可复现。

## 1. 设计目标

### 1.1 一句话

**正交俯视、一屏一屋的房间制梦域**：玩家在矿工的巡逻缝隙里移动、观察朝向、选择从背后下手；接敌后进入独立回合制战斗（见战斗文档）。

### 1.2 体验支柱

| 支柱 | 含义 | 落到系统 |
| --- | --- | --- |
| 看得懂 | 竖屏小屏也能一眼读出墙、路、门、敌人朝向 | 硬边 tile、朝向箭头、警戒图标、房间不超出两屏 |
| 潜得动 | 不靠反应，靠观察巡逻路线和视线 | 巡逻路径、视锥、听觉、掩体、善变 |
| 先手值钱 | 从背后接近能改变战斗开局 | 背袭/侧袭/正面/被袭四档接敌 |
| 每卷换皮 | 七个梦主七套空间语言 | 每卷独立 tileset / 心防规则 / 色调 |
| 不添堵 | 手机竖屏、单手可玩、失败有退路 | 摇杆 + 大按钮、锚点、自动存档 |

### 1.3 不做

- 不做开放世界、无缝大地图、程序生成迷宫。
- 不做实时动作战斗；地图攻击只负责“接敌 + 先制判定”。
- 不做地图编辑器产品功能；M1 用手写 JSON + Tiled 可选导出。
- 不做多人、联机、UGC。

## 2. 核心循环

```
现实调查（小地图 / NPC / 线索）
  → 选锚点潜入
  → 梦域房间探索（移动 / 观察 / 潜行 / 解谜）
  → 接敌判定（背袭 / 侧袭 / 正面 / 被袭）
  → 独立战斗场景（回合制，见 DESIGN-BATTLE）
  → 回到地图（敌人清除 / 门解锁 / 掉落）
  → 锚点存档 / 下一房间
  → Boss（心防规则）→ 解离梦主 → 现实推进
```

| 动词 | 输入 | 结果 |
| --- | --- | --- |
| 走 | 左摇杆 / WASD | 8 方向移动，撞墙滑行 |
| 跑 | 摇杆推到底 / Shift | 速度 +65%，噪音半径扩大 |
| 蹲行 | 长按潜行键 | 速度 −45%，不产生脚步声 |
| 看 | 靠近可交互物 | 提示气泡、调查/开门/拾取 |
| 打 | 攻击键 | 地图近战弧；命中巡逻敌人即接敌 |
| 变 | 善变键 | 消耗伪装槽，敌人短暂不认人 |
| 锚 | 锚点交互 | 存档 / 回血 / 传送 / 休整 |

## 3. 视角、尺度与镜头

### 3.1 基准

| 项 | 值 | 说明 |
| --- | --- | --- |
| 设计宽 | **720** | 固定，所有坐标按 720 写 |
| 设计高 | **1280–1600** | 由视口比例算，底部 UI 贴底、场景区拉伸 |
| tile | **64×64 设计单位** | 32×32 美术像素 × 2（见 ART-STYLE） |
| 标准房 | **12×20 tile** = 768×1280 | 横向只比屏幕多 48，几乎不横移 |
| 大房 | 16×28 tile | 大厅 / Boss 前厅 |
| 走廊 | 6×10 tile | 连接房，强制纵向构图 |
| 可见范围 | 11.25 列 × 20–25 行 | 竖屏天然适合“纵深”，不适合横向大平原 |

- **正交俯视（正上方）**：相机垂直向下看地面，正方形 tile 网格；和「游戏素材大师」的俯视地图编辑器同一视角。不做 3/4、不做等距菱形、不做 45° 旋转、不做墙面透视。
- 墙、柱、家具都是俯视平面 tile/贴图；高度感只靠描边、阴影和层叠，不画“正面墙 + 顶面”的立面。
- 角色用 8 向 top-down sprite（四正 + 四斜各一套），不是 3/4 侧身立绘；朝向由 sprite 与脚下小箭头共同表达。

### 3.2 角色与碰撞

| 对象 | 美术尺寸 | 设计尺寸 | 碰撞盒（脚下） |
| --- | --- | --- | --- |
| 玩家 | 32×48 | 64×96 | **36×24**，贴脚底 |
| 普通敌人 | 48×64 | 96×128 | 48×28 |
| 精英 | 64×80 | 128×160 | 64×32 |
| Boss | 96×96 起 | 192×192 起 | 96×48 |
| 门 | 1 tile | 64×64 | 无，触发区 |

碰撞盒只覆盖脚底，允许上半身与墙、柱子视觉重叠，避免“人物被墙吃掉一半”的廉价感；遮挡用前景层和半透明处理。

### 3.3 镜头

- 相机沿用 `applyCamera()`：`setZoom(plan.scale)` + `centerOn(360, designH/2)`。
- 地图不再叠一层世界缩放；像素素材按 2× 设计尺寸导出或整数放大。
- `startFollow(player, true, 0.12, 0.12)`，deadzone **160×240**，避免微小移动就晃镜头。
- 相机 bounds = 房间像素边界；房间小于视口时居中，不露出房外。
- 震屏只用于受击/重物落地；`prefers-reduced-motion` 时关闭震屏与冲刺残影。
- 房间切换：淡出 180ms → 重定位 → 淡入 180ms；期间锁输入 0.35s。

### 3.4 竖屏画面分区

```
┌────────────────────────────┐
│ 目标条                小地图 │ 0–96
├────────────────────────────┤
│                            │
│         场景 / 房间          │ 96–(H-200)
│                            │
├────────────────────────────┤
│ 摇杆             攻击 交互   │ H-200–H
└────────────────────────────┘
```

- 顶部 96、底部 200 为 HUD 安全区；房间内容不得把关键信息只放在这两条带里。
- 设计高 1600 时，多出的 320 全部给场景区，HUD 仍贴底。

## 4. 关卡结构：房间图

### 4.1 一章 = 一个房间图

每章 **8–12 个房间**，不是一张连续大地图。房间类型：

| 类型 | 作用 | 数量 |
| --- | --- | --- |
| 入口房 | 玩家从锚点进入的落点，教学/氛围 | 1 |
| 回廊 | 连接、巡逻、第一次接敌 | 2–3 |
| 探索房 | 支线宝箱、线索、可选战斗 | 2–3 |
| 锚点房 | 存档/休整，通常在中段 | 1 |
| 主厅 | 解谜/机关/精英 | 1 |
| Boss 前厅 | 不可回头点、补给 | 1 |
| Boss 房 | 心防战场 | 1 |

### 4.2 房间图示例（卷一·宫廷）

```
[锚点·序]──[入口]──[丹陛回廊]──[中庭]──[王座前厅]──[Boss·王座]
                         │            │
                     [侧殿·宝箱]   [锚点·中庭]
```

- 实线 = 双向门；侧殿是可选支线，用“锁 + 钥匙旗标”控制。
- 中庭是回环枢纽：玩家可以绕开一组巡逻，也可以正面清掉拿素材。
- Boss 前厅关门后不可回退；进入前自动提示“是否休整”。

### 4.3 房间状态

| 状态 | 含义 | 存盘点 |
| --- | --- | --- |
| `unvisited` | 未进入，小地图只显示轮廓 | 否 |
| `visited` | 进入过，显示门与锚点 | 房间切换时 |
| `cleared` | 精英/Boss 已清除，或关键旗标完成 | 战斗胜利时 |
| `locked` | 门被旗标锁住 | 否 |

小地图只画**房间图**，不画 tile 级地图：当前房间高亮、已访问房间实线、未访问虚线、锚点/宝箱/Boss 用图标。竖屏右上角 160×150 足够。

## 5. 地图数据格式

### 5.1 原则

- **房间是唯一数据单位**，一章一个 `rooms/*.json` 或一个 `chapter.room.ts` 汇总；不进运行时热更。
- 用 ASCII 画碰撞与地标，方便 review diff；对象用数组补充。
- 构建期校验：行宽、边界、出生点、门连通、巡逻点可走、锚点唯一、旗标引用存在。
- M1 不做运行时地图编辑器；Tiled 只作为可选导出源，导出后仍要过校验脚本。

### 5.2 类型契约

```ts
type TileChar = '#' | '.' | ',' | '=' | 'A' | 'P' | 'C' | 'E' | '~';

interface MapRoom {
  id: string;                 // ch01.entry
  chapter: string;            // ch01
  title: string;              // 梦域·丹陛回廊
  size: [number, number];     // [w, h]，w*64 × h*64 设计单位
  tileset: string;            // dream.palace
  ascii: string[];            // h 行，每行 w 个字符
  links: DoorLink[];
  objects: MapObject[];
  minimap: [number, number];  // 房间图坐标，格子单位
  bgm?: string;
  rule?: string;              // 心防规则 id
  note?: string;
}

interface DoorLink {
  at: [number, number];              // ascii 中 '=' 的坐标
  to: { room: string; at: [number, number] };
  lockedBy?: string;                 // 旗标 / 钥匙
  label?: string;                    // “通往中庭”
}

type MapObject =
  | { type: 'spawn'; id: string; at: [number, number]; facing: 'up' | 'down' | 'left' | 'right' }
  | { type: 'anchor'; id: string; at: [number, number]; title: string }
  | { type: 'chest'; id: string; at: [number, number]; loot: string; flag: string }
  | { type: 'patrol'; id: string; enemy: string; path: [number, number][]; pauseMs?: number; facing?: 'up' | 'down' | 'left' | 'right' }
  | { type: 'trigger'; id: string; at: [number, number]; size: [number, number]; event: string; once?: boolean }
  | { type: 'npc'; id: string; at: [number, number]; speaker: string; script: string }
  | { type: 'cover'; id: string; rect: [number, number, number, number]; kind: 'bush' | 'shadow' | 'curtain' }
  | { type: 'hazard'; id: string; rect: [number, number, number, number]; kind: string; damage: number };
```

坐标一律用 **tile 整数坐标**；运行时换算 `x * 64 + 32`（格中心）。角色脚底点单独存 `design x/y`。

### 5.3 ASCII 图例

| 字符 | 含义 | 可走 |
| --- | --- | --- |
| `#` | 墙 / 实心障碍 | 否 |
| `.` | 地面 | 是 |
| `,` | 装饰地面（地毯/草/水纹） | 是 |
| `=` | 门（必须配 `links`） | 是，触发 |
| `A` | 锚点（必须配 `objects`） | 是 |
| `P` | 默认出生点（必须配 `spawn`） | 是 |
| `C` | 宝箱（必须配 `chest`） | 是 |
| `E` | 巡逻起点（必须配 `patrol`） | 是 |
| `~` | 不可走装饰（矮墙/深渊） | 否 |

> 示例里的 `ascii` 省略号只用于文档缩短；真实数据必须完整 20 行、每行 12 字符。

### 5.5 校验规则

1. `ascii.length === size[1]`，每行长度 `=== size[0]`。
2. 最外圈必须是 `#` 或 `=`。
3. 每个 `P` 有且只有一个 `spawn`；每个 `A` 有且只有一个 `anchor`；每个 `C` 有且只有一个 `chest`；每个 `E` 有且只有一个 `patrol`，且巡逻路径首点等于该格。
4. 每个 `=` 有且只有一个 `links`；双向门两侧 `to` 互为回指。
5. 巡逻 `path` 的每一点必须是可走格，且相邻点可直线到达。
6. 所有门、锚点、宝箱从出生点可达（BFS，考虑 `lockedBy` 时按解锁后算）。
7. `rule` / `lockedBy` / `loot` / `event` 必须在注册表里存在。
8. `minimap` 不与其他房间重叠。

## 6. 移动、碰撞、镜头

### 6.1 输入

| 输入 | 触屏 | 键盘（调试） |
| --- | --- | --- |
| 移动 | 左下浮动摇杆（半径 96） | WASD / 方向键 |
| 跑 | 摇杆推到底（>0.85） | Shift |
| 蹲行 | 长按潜行键 | Ctrl |
| 攻击 | 右下攻击键 | J |
| 交互 | 右下交互键（自动显隐） | E |
| 善变 | 侧边变身键 | Q |
| 冲刺 | 双击摇杆 / 冲刺键 | Space |
| 暂停 | 右上角 | Esc |

摇杆 200×200 设计单位的响应区，knob 88；攻击/交互按钮 ≥ 112 设计单位（约 60 CSS px），保证拇指命中。

### 6.2 参数

| 参数 | 值 |
| --- | --- |
| 走速 | 170 设计单位/秒（约 2.65 tile/s） |
| 跑速 | 280（−65% 转向灵敏度） |
| 蹲速 | 95 |
| 加速度 / 减速度 | 900 / 1400 |
| 冲刺 | 420，持续 0.18s，冷却 1.2s |
| 脚步噪音半径 | 走 1.5 tile / 跑 4 tile / 蹲 0 |
| 攻击弧 | 前方 120°，96 设计单位 |

### 6.3 碰撞

- 8 方向输入先归一化，避免斜向加速。
- **分轴解算**：先 X 后 Y；撞墙时保留另一轴速度，自动贴墙滑行。
- 拐角不切角：斜向移动若 X/Y 单独都不可走，则整体停住。
- 门洞、走廊最小宽度 1 tile；玩家碰撞盒 36 宽，留 28 的容错。
- 斜坡/台阶不做高度，改为“视觉台阶 + 可走地面”。

### 6.4 朝向与动画

- 角色 8 向朝向（上/下/左/右 + 四斜），输入两轴占比接近时取斜向；停下保留最后朝向。
- 状态机：`idle → walk / run / sneak → attack → hurt → interact`。
- 攻击时锁移动 0.25s；受击 0.2s 无敌帧（地图不主打动作，只防连击）。
- 像素 sprite 用 NEAREST；残影/光效用 LINEAR。

### 6.5 深度排序

- 地面层固定 depth 0；地面贴花 10。
- 所有“会挡人”的对象按**脚底 y** 排序：`depth = 100 + y`。
- 前景层（吊灯、门框、树冠）固定 9000，玩家走到后面时对该前景 sprite 做 0.45 透明度渐变。
- 敌人、玩家、宝箱同一套规则，避免“站在宝箱后面却画在宝箱上”。

## 7. 交互与锚点

### 7.1 交互规则

- 候选：距离 ≤ 88 设计单位，且大致在朝向侧（背后交互用“附近最近”兜底）。
- 同时多个候选时优先级：剧情触发器 > 门 > 锚点 > 宝箱 > NPC > 可破坏物。
- 交互提示用浮动气泡 + 图标，不写长句；长文案进对话框。
- 交互锁移动 0.2s，防止连点开门。

### 7.2 锚点

锚点是存档点、复活点、传送点，也是剧情里的“时空裂缝”。

| 功能 | 规则 |
| --- | --- |
| 自动存档 | 进入房间、战斗胜利、交互锚点时自动写档（预览模式不写） |
| 回血 | 全队回复 50% HP/EP，消耗 1 点稳定度 |
| 传送 | 已发现锚点之间传送，消耗 1 点稳定度 |
| 稳定度 | 每章 3 点；章节完成或剧情休息恢复；为 0 时仍可存档，但不能回血/传送 |
| 阵亡复活 | 回到最后锚点，不消耗稳定度，敌人重置，HP/EP 50% |
| 预览 | `StageLaunchContext.preview === true` 时禁写档、禁传送，UI 显示“预览模式” |

> 稳定度是剧情“短时间三次需休息 24h”的可玩化改编，不改原文规则；数值只在本文维护，若后续要写进剧情文本再在 `STORY-BIBLE.md` 登记。

### 7.3 门、宝箱、触发器

- 门：`lockedBy` 旗标满足才开；开门动画 0.4s；Boss 门反向锁，进战后不可退。
- 宝箱：一次性 `flag`；打开后换成开启贴图；掉落进战斗/背包系统（M2）。
- 触发器：矩形区，进入即发；`once` 控制是否重复；事件交给剧情模块，不在场景里硬编码台词。
- NPC：`script` 指向 `src/story/` 的对话数据；地图只负责朝向与交互。

### 7.4 地图攻击

- 攻击键触发前方 120°、96 距离的弧；可打碎罐子/藤蔓，也可打中巡逻敌人。
- 命中未警觉敌人 → 进入接敌判定（见 §9），**不是**直接秒杀。
- 命中已警觉敌人 → 正常接敌，敌人先手。
- 只有剧情脚本（如 Boss 核心已破）允许地图处决，避免玩家绕过战斗系统。

## 8. 巡逻、视线与潜行

### 8.1 敌人状态机

```
PATROL ──看见/听见──► SUSPICIOUS ──1.0s──► CHASE ──接触──► 接敌
   ▲                      │                  │
   │                      └──失去目标 1.5s──┘
   └────────── RETURN ◄──────── 丢失 4s / 超出拴绳 8 tile
```

| 状态 | 行为 | 玩家应对 |
| --- | --- | --- |
| `PATROL` | 沿路径走，到点停 0.9–1.2s，左右扫视 ±60° | 绕背、等转身 |
| `SUSPICIOUS` | 停步、转向可疑点、头顶 `?`，警戒条 0→1 | 蹲下/进掩体/停止跑动 |
| `CHASE` | 追击，头顶 `!`，移速 240；进入 48 触发接敌 | 拉开、绕柱、抢先手 |
| `RETURN` | 返回出生点，不回血但重置警戒 | 跟背、卡视野 |

### 8.2 视线

- 视锥：**120°**（±60°），距离 **4.5 tile**；精英 5.5 tile。
- 视线遮挡：每 0.15s 对玩家脚底做一次 tile 级 raycast，墙/柱/关着的门阻断。
- 警戒条增速：`0.9/s × 距离系数 × 光照系数 × 姿态系数 × 伪装系数`。
  - 距离系数 `clamp(1 - dist/range, 0.25, 1)`；
  - 蹲下 ×0.55；跑动 ×1.4；善变 ×0（除非贴脸 1 tile）；
  - 掩体（草丛/阴影/帘幕）内 ×0.25；心防规则可改写。
- 脱离视线 1.5s 后警戒条以 `0.6/s` 衰减；到 0 回 `PATROL`。
- 听觉：跑动 4 tile、走路 1.5 tile、攻击 5 tile；听到后进入 `SUSPICIOUS` 并走向声源，不直接开战。

### 8.3 追击与寻路

- 8 方向 A*，网格上限 400 节点；禁止贴角斜穿。
- 路径每 0.5s 重算一次；目标点被占时停在 40 距离外。
- 拴绳：离出生点 > 8 tile 或丢失目标 4s → `RETURN`。
- 追击中不触发其他敌人的“连锁仇恨”；但同房间敌人被攻击会共享一次警觉（+0.5）。

### 8.4 善变（地图版）

剧情里“解命中后变成目标、读取记忆、限时”。地图上做成可玩的潜入资源：

| 项 | 规则 |
| --- | --- |
| 槽位 | 100 点，每秒 −1.2；锚点/特定道具回复 |
| 启动 | 需先在地图战斗中完成一次“解离”解锁该敌人类型（M2） |
| 效果 | 同类型普通矿工不主动识破；视线判定视为“梦中人” |
| 破绽 | 贴脸 1 tile、主动攻击、交互关键物、跑动撞人都会暴露 |
| 退出 | 手动解除 / 槽位耗尽 / 受击；退出后 3s 内无法再变 |
| 预览 | 可用，但不写“已解锁”进度 |

M1 只做“通用伪装”，不做“变成具体 NPC 套话”；套话留给 M2 的剧情系统。

### 8.5 接敌窗口

- 敌人进入 `CHASE` 且距离 < 3 tile 时，头顶闪 `!` 0.4s，这是玩家的“先制窗口”。
- 窗口内按攻击且面朝敌人 → 走 §9 的接敌判定，玩家可能拿到背袭/侧袭。
- 窗口结束或敌人接触（48 距离）→ 敌人先手接敌（`enemy` 档）。
- 这样“被发现”仍有 0.4s 反应，不至于摸到就进战斗。

## 9. 接敌与偷袭判定

### 9.1 角度判定

用敌人朝向向量与“敌人 → 玩家”的单位向量求点积：

```ts
const toPlayer = normalize(playerPos - enemyPos);
const cos = dot(enemyFacingVec, toPlayer);

if (cos <= -0.5) grade = 'back';   // 玩家在敌背后 120° 扇区
else if (cos >= 0.5) grade = 'front'; // 正面 60°
else grade = 'side';               // 侧翼
```

只有敌人处于 `PATROL` / `SUSPICIOUS` 且未发现玩家时，`back` / `side` 才成立；已经 `CHASE` 一律按 `front` 或 `enemy`。

```
            敌人朝向 →
   [玩家·背后]   (敌人)   [正面]
        back      side      front
```

### 9.2 四档接敌

| 判定 | 条件 | 战斗开局（详见战斗文档 §9） |
| --- | --- | --- |
| **背袭** | 未警觉 + 背后 120° + 玩家先攻击 | 我方先制 1 轮；敌人背对我方入口排；首次命中必背刺；伪装直接破碎 |
| **侧袭** | 未警觉 + 侧翼 | 我方先制 1 轮；不自动背刺 |
| **正面** | 未警觉但正面，或已警觉 | 按 SPD 正常排序 |
| **被袭** | 追击接触 / 玩家被抓住 | 敌方先制 1 轮；我方首轮不回 EP |

### 9.3 地图 → 战斗契约

```ts
interface EncounterRequest {
  battleId: string;                 // battle.ch01.corridor
  seed: number;
  ambush: 'back' | 'side' | 'front' | 'enemy';
  entryWing: 'left' | 'right';      // 玩家从哪一侧进入战场
  enemies: { id: string; slot: 0 | 1 | 2; facing: 'left' | 'right' }[];
  source: { roomId: string; objectId: string };
  rule?: string;                    // 心防规则
}

interface EncounterResult {
  outcome: 'victory' | 'escape' | 'defeat';
  rounds: number;
  party: { id: string; hp: number; ep: number }[];
  defeated: string[];               // 敌人实例 id
  loot: string[];
  seed: number;
  logHash: string;                  // 回放/验收
}
```

- `entryWing`：玩家从敌人左侧接近 → `left`，右侧 → `right`；背袭时敌人初始朝向背对该侧。
- 队伍站位沿用上一场战斗；接敌时先保证入口侧至少 1 人（优先郑卿/周全），若入口侧已满 2 人，第三人自动放另一侧，第四人补空位。
- `seed = hashSeed(saveSeed, chapter, roomId, objectId, encounterCount)`；同存档同遭遇可复现。
- 战斗包 `battle.common + battle.<id>` 在进入接敌区时预取，用白闪/碎裂转场遮住加载。

### 9.4 战后回写

| 结果 | 地图侧 |
| --- | --- |
| 胜利 | 移除敌人实体、标记 `cleared`、开门/掉宝、自动存档（预览不写） |
| 撤退 | 玩家退到接敌前 2 tile，敌人保持警觉并恢复 30% maxHP；不自动存档 |
| 失败 | 回最后锚点，敌人重置，队伍 50% HP/EP；不消耗锚点稳定度 |

## 10. 心防（地图规则）

心防是梦主潜意识的一条“荒诞但致命”的规则，每卷至少一条，地图与 Boss 战共用同一份数据。

```ts
interface DomainRule {
  id: string;
  title: string;
  text: string;                     // 进入梦域时的规则卡
  canRun?: boolean;
  alertMultiplier?: number;
  onEnterRoom?(ctx: RuleContext): void;
  onTick?(ctx: RuleContext, dtMs: number): void;
  onViolate?(ctx: RuleContext): void;
  battleRuleId?: string;            // 同一规则在战斗里的版本
}
```

| 示例 | 规则 | 玩法后果 |
| --- | --- | --- |
| 宫廷·僭越 | 王座厅内不可背对王座（不可向下走） | 向下移动累积“僭越”，3 层触发禁卫巡逻 |
| 游乐园·不许跑 | 梦域内禁止奔跑 | 跑动 0.5s 立即全场警觉 |
| 武侠·冰狱 | 冰面滑行，松手继续滑 2 tile | 转弯/停步变难，接敌角度更难控制 |
| 剧院·追光 | 聚光灯外视线判定 ×2 | 必须贴着光斑走，路线被限制 |

规则必须**进场可见**（规则卡 + HUD 图标 + 违规反馈），不做隐藏惩罚。预览参数 `rule=` 可强制某条规则，方便验收。

### 11.1 布局（720 宽基准）

| 目标条 | 左上 (24, 24) | 360×64 |
| 小地图 | 右上 (536, 20) | 160×150 |
| 暂停 | 右上角 (656, 20) | 64×64 |

| 警戒眼 | 玩家头顶 | 48×48 |
| 交互气泡 | 目标上方 | 自适应，最大 240 宽 |

### 11.2 可读性

- 敌人朝向用**地面箭头 + 头顶小三角**双重表达，不只靠 sprite 翻转。
- 警戒状态：`?` 黄、`!` 红，配脉冲；色盲也能靠形状区分。
- 可交互物有 1px 鎏金描边；不可交互的宝箱不开描边。
- 暗处保留 0.35 的基础亮度，不能黑到看不清巡逻路线。

### 11.3 单手与安全区

- 所有高频操作在右下拇指区；摇杆可浮动（按哪里哪里是中心）。
- 按钮间距 ≥ 16 设计单位，防误触。
- 顶部安全区避开刘海/状态栏；底部避开手势条。
- 1200×648 横屏（桌面/平板）时画面居中留边，HUD 仍按 720 宽设计，不重排。

## 12. 美术、资源与性能

### 12.1 美术

- 每卷一套 tileset + props，主色按 ART-STYLE：宫廷金红、游乐园糖果、武侠水墨冷光……
- tile 32×32 美术像素；墙用 3×3 bitmask 自动拼接（47 图块），地面 4–6 种变体按 seed 撒。
- 俯视分层：地面 → 墙/柱 → 角色 → 前景 → 光照/浮尘 → 暗角。地图本身不改变透视；光效用加法混合的 sprite，不做实时光照。
- 同屏最多 4 个加色光源；低端机降级为 1 个 + 暗角。

### 12.2 资源与预算

| bundle | 内容 | 预算 |
| --- | --- | --- |
| `map.common` | 交互图标、警戒图标、通用 UI、玩家地图图集 | ≤ 2 MB |
| `map.<chapter>` | 本章 tileset、props、房间 JSON、BGM | ≤ 6 MB |
| `battle.common` | 战斗 UI/技能图标/特效 | ≤ 3 MB |
| `battle.<id>` | 单场战斗背景/敌人图集 | ≤ 5 MB |

- 房间 JSON 单房 ≤ 24 KB；一章合计 ≤ 200 KB。
- 图集 1px extrude + 2px padding；tileset 单张 ≤ 2048×2048。
- 禁止在场景里 `this.load.*`；所有资源进 `bundles.ts`，跑 `assets:scan` + `assets:check`。

### 12.3 性能

- 同房间最多 8 个巡逻敌人；超出用脚本触发器分批激活。
- 敌人 AI 每 0.15s 一次视线检测，每 0.5s 一次寻路；远处（>1.5 屏）休眠。
- 粒子池复用；战斗/地图转场不新建纹理。
- 目标 60fps；低端机允许 30fps，降级顺序：关体积光 → 关残影 → 降粒子 → 关前景透明度渐变。

## 13. 存档、确定性与预览

### 13.1 存档结构

```ts
interface MapProgress {
  version: 1;
  chapter: string;
  roomId: string;
  at: { x: number; y: number };
  facing: 'up' | 'down' | 'left' | 'right';
  anchorId: string;
  anchorStability: number;          // 0–3
  flags: Record<string, boolean | number>;
  visited: string[];
  cleared: string[];
  defeated: string[];               // 敌人实例 id
  party: { id: string; hp: number; ep: number }[];
  playTimeMs: number;
  seed: number;
}
```

- 写档点：房间切换、战斗胜利、锚点交互。战斗中不写档。
- 版本迁移：`version` 不匹配时走迁移函数；M1 只支持 v1。
- 预览模式：只读；`launchStage()` 注入的 `preview` 为 true 时禁用写档/传送/成就。

### 13.2 确定性

- 巡逻相位、地面变体、掉落、AI 犹豫时间全部走 `src/dev/random.ts` 的 `mulberry32` / `hashSeed`。
- 禁止 `Math.random()` / `Date.now()` 参与玩法；动画缓动可以用时间，但不能影响判定。
- 同一 seed + 同一操作序列 → 同一巡逻路线/接敌判定/战斗开局。

### 13.3 舞台预览

地图作为可玩场景必须登记 `src/dev/stage-catalog.ts` 和 `scene-keys.ts`：

| stage id | 内容 | 验收 |
| --- | --- | --- |
| `scene.ch01.entry` | 标准房，锚点/宝箱/巡逻 | 构图、HUD、交互 |
| `scene.ch01.patrol` | 专门测背袭/侧袭/被袭的三条巡逻 | 接敌判定、四档开局 |
| `scene.ch01.throne` | 心防规则房 | 规则卡、违规反馈 |
| `scene.ch01.boss-gate` | Boss 门前 | 锁门、不可回退 |

`options`：`room`、`state=default|cleared`、`seed`、`rule`。未知房间 id 回退到 `ch01.entry` 并在控制台 warning，不白屏。退出路径：暂停 → 返回标题；不需要打通。

按 AGENTS 约定，判定逻辑不 import Phaser，放 `src/map/core/`：

src/map/

## 16. 开放问题

1. **房间制 vs 连续地图**：本文选一屏一屋；如果后续想要更开放的梦域，需要先解决竖屏横向视野和包体预算。
2. **现实线是否复用地图**：建议复用（学校/家/医院用同一套系统，只是无巡逻、多 NPC），但现实线更偏对话，需要单独的“调查模式”UI。
3. **队伍上限**：地图上只显示队长，战斗 4 人；是否需要“队友跟随”表现？
4. **善变的解锁节奏**：按敌人类型解锁会不会逼玩家重复战斗？备选：剧情节点直接给 2–3 种伪装。
5. **锚点稳定度**：3 次/章是否太紧？需要首章实测后再调。
6. **小地图是否显示敌人**：当前不显示；如果测试反馈“找不到路”，再考虑只显示“警觉中的敌人”。
